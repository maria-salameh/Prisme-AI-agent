# Checkpoint J4-03 — La chaîne d'intégration continue, et un README pour l'inconnu

Écrivez `.github/workflows/ci.yml` : il se lance à chaque push sur `main` et à chaque pull request, avec trois jobs qui tournent sur `ubuntu-latest` : `npm run lint`, `npm test` (vos tests unitaires) et `npm run e2e` (des tests de bout en bout du serveur, dans `tests/e2e/`). Ces scripts existent dans votre `package.json`. Le premier palier vérifie le fichier et rejoue ces trois étapes : vertes sur votre `main`, et rouges sur une copie de `brain.js` que j'abîme.

Écrivez aussi un `README.md` pour quelqu'un qui ne connaît pas le projet, avec les sections Objectif, Installer, Lancer, Tester, Modules et API. Je le suis à la lettre dans un dossier neuf : mes commandes de « Lancer » et de « Tester » doivent marcher, et il faut un tag `v1` sur un commit de `main`. C'est le second palier.

Pour le bonus, un fichier `openapi.json` décrit `POST /api/chat` et `GET /api/health`, et votre serveur répond vraiment `{ "status": "ok" }` sur `/api/health`. Poussez avant le gel.
